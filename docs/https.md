# HTTPS on your local network

HTTPS allows the browser on your phone or Raspberry Pi to request microphone
access. You still need to grant permission when starting a recording.

```text
Phone / Pi -- HTTPS :8443 --> Caddy -- localhost :5001 --> Waitress / Neuro Atlas
```

Each device renders the 3D model in its own browser. The OpenAI API key stays in
the Python process on the server.

## One-time server setup

Install the additional Python dependencies from the project directory:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Also install [Caddy](https://caddyserver.com/docs/install). On Windows, you can
extract `caddy.exe` from the official
[release archive](https://github.com/caddyserver/caddy/releases) into
`.tools/caddy.exe`. Verify the download against the published checksums.
The launcher also finds Caddy on `PATH`; use `--caddy PATH` to specify its location.

For a browser on the Pi itself, prefer the local `http://localhost:5000`
launcher from the README; HTTPS is only needed for other LAN clients. Set
`NEURO_GESTURES=1` when starting this launcher to enable the Pi camera.

On a Pi running Raspberry Pi OS 64-bit, use the Linux ARM64 version of Caddy and
a Python environment created on the Pi. Do not copy the Windows `.venv`:

```bash
.venv/bin/python -m pip install -r requirements.txt
# If you downloaded the executable manually into .tools:
chmod +x .tools/caddy
```

The launcher generates its Caddy configuration in `.local/https/Caddyfile`;
a root-level Caddyfile is not required.

## Starting the server

Find the server's current IPv4 address using `ipconfig` on Windows or
`hostname -I` on the Pi. Choose the address of its active Wi-Fi or Ethernet
adapter. In a terminal with your `OPENAI_API_KEY` already set, run:

```powershell
.\.venv\Scripts\python.exe -m main.https_server --host 192.168.1.213
```

On Linux or Raspberry Pi:

```bash
.venv/bin/python -m main.https_server --host 192.168.1.213
```

Replace the example IP with the address of the computer running the server.
Open **https://192.168.1.213:8443**. On the server itself, you can also use
**https://localhost:8443**. Press `Ctrl+C` to stop both processes.
Use `--port` and `--backend-port` if you need different ports.

The launcher waits for both services and verifies HTTPS against the generated
certificate chain before printing the address. It copies the public root
certificate to `.local/https/share/neuro-atlas-root.crt` and prints its SHA-256
fingerprint. Caddy automatically renews the certificates for individual addresses.

If Windows asks for firewall permission for Caddy, allow access on your private
network. Clients need TCP port 8443. The backend on port 5001 only listens on
`127.0.0.1`. No router port forwarding is required. The old HTTP server on port
5000 runs separately; stop it when you no longer need it. This setup does not
open an additional HTTP port for redirects.

## Trusting the certificate on each client

A new device does not yet trust your local certificate authority. Copy **only**
`.local/https/share/neuro-atlas-root.crt` to your own devices, for example using
USB or AirDrop. This file is public and contains no private key. Keep the other
files in `.local/https` on the server. The web server does not serve this folder.

Installing a root certificate allows the device to trust certificates issued by
that authority. Only install the certificate generated by your own server.
Clicking through a certificate warning is not a substitute for setting up trust.
Fully restart the browser after installing the certificate.

### Windows, including the server PC

From the project directory, install the public certificate for the current
Windows user:

```powershell
certutil -user -addstore Root .\.local\https\share\neuro-atlas-root.crt
```

This changes that user's certificate store. The HTTPS launcher never performs
this step automatically.

### iPhone / iPad

1. Open the transferred certificate file.
2. Go to **Settings -> General -> VPN & Device Management** and install the
   downloaded certificate profile.
3. Go to **General -> About -> Certificate Trust Settings** and enable full trust
   for the installed Caddy certificate authority.
4. Open the HTTPS address and allow microphone access when starting a recording.

[Apple: Trust manually installed certificate profiles](https://support.apple.com/en-us/102390)

### Android

In the security settings, choose **Encryption & credentials -> Install a
certificate -> CA certificate** and select the file. Menu names vary by
manufacturer; search settings for "install certificate" if needed.
Then open the HTTPS address in your browser and allow microphone access.

[Google: Add and remove certificates](https://support.google.com/pixelphone/answer/2844832?hl=en)

### Raspberry Pi OS

Copy the public certificate to the Pi and install it in the system certificate
store:

```bash
sudo install -m 644 neuro-atlas-root.crt /usr/local/share/ca-certificates/neuro-atlas-root.crt
sudo update-ca-certificates
```

If Chromium still shows a certificate warning, import the same file as a trusted
certificate authority using the browser's certificate manager. A mismatched IP
address or an incorrect system clock can also cause a certificate warning.

## What is stored in .local/https?

Caddy creates a local certificate authority on the first start. Its root signs
an intermediate authority, which issues the server certificates for addresses
such as `192.168.1.213` and `localhost`:

```text
Trusted root certificate -> Intermediate certificate -> Server certificate
```

The browser checks that chain, the server address, and certificate validity.
The server also proves possession of its private key during the TLS handshake.
Once the connection is trusted, the page qualifies as a secure context and can
request microphone access. Installing the certificate does not grant microphone
permission by itself.

| File or directory | Purpose | Copy to clients? | Commit to Git? |
| --- | --- | --- | --- |
| `share/neuro-atlas-root.crt` | Public root certificate exported for installation | Yes | No; specific to this installation |
| `caddy/pki/authorities/local/root.crt` | Original public root certificate | Use the exported copy instead | No |
| `caddy/pki/authorities/local/root.key` | Private signing key of the root authority | No | No |
| Other files under `caddy/` | Intermediate keys, server certificates, private keys and Caddy state | No | No |

The root certificate contains a **public key**, not the secret signing key.
Sharing the certificate does not let someone issue new certificates. The private
keys must stay private. Trust in this root applies to certificates it issues,
not just to the Neuro Atlas application.

Keep `.local/https` between starts. If you delete it, Caddy creates a new authority,
and your devices must trust the new root certificate. A fresh Git clone generates
its own authority because this installation-specific state is intentionally
excluded from Git. Changing the server IP and restarting with the new `--host`
does not replace an existing authority.

## Verification and operation

- The HTTPS page should load without a certificate warning.
- With the assistant configured, **Mikrofon starten** (Start microphone) is
  enabled. Recording also requires browser permission and an available microphone.
- Over the old HTTP network address, microphone access stays blocked. A visible
  message below the buttons explains why; text chat remains available.
- If the server IP changes, restart with the new `--host` address. A DHCP
  reservation in your router keeps that address stable.
- The launcher runs in the foreground. Automatic startup can be configured
  later as a system service.
- This setup is intended for your private network and has no login mechanism.
  HTTPS does not replace authentication for a public deployment.

The original development command, `python -m main.brain_viewer`, remains
available. HTTPS sessions use a separate cookie name with `Secure`, `HttpOnly`
and `SameSite=Strict`. The proxy preserves the original host, and Waitress reports
HTTPS as the request scheme so that the existing origin checks continue to work.

Commit `Caddyfile`, `main/https_server.py`, `requirements.txt`, the
documentation and tests. Keep `.local/`, `.tools/`, `.venv/`, `.env` files and
generated verification output out of Git. These paths are covered by `.gitignore`;
certificate and private-key extensions are also ignored as protection for copies
saved outside `.local/`. An `.env.example` may contain placeholders only.

Technical references: [Caddy Local HTTPS](https://caddyserver.com/docs/automatic-https#local-https),
[Waitress behind a reverse proxy](https://docs.pylonsproject.org/projects/waitress/en/stable/reverse-proxy.html).
